## Remaining approved targets and defensible limits

- **Other seven DeepSeek V4.1-Flash max developer harnesses** (`claude-code`, `codex`, `opencode`, `pi`, `dsh-minimal`, `dsh-standard`, `dsh-ptc`): [DeepSeek's Table 4](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/resolve/main/DeepSeek_V41_Tech_Report.pdf) reports scores across different scaffolds, not usage. Fireworks' $0.430/task can be shown as an **external same-model/effort budget reference** for each, but no harness-specific cost or output-token estimate is identified. The V4 Flash predecessor mini-swe measurement cannot be assigned to these seven different agent loops. DeepSeek's [API pricing](https://api-docs.deepseek.com/quick_start/pricing/) identifies `deepseek-flash` as V4.1-Flash, but varying input/cache/output counts and pricing windows prevent task costing from a rate card alone.
- **MiMo-V2.6 Pro/Flash**: both separate Table 3 rows and separate Figure 3 `average@3` training endpoints lack inference token counts, harness and effort. [Xiaomi's September 22 announcement](https://mimo.xiaomi.com/mimo-v2-6/article), “Availability / API,” specifies per-million **cached input / uncached input / output** prices: Pro `$0.0036 / $0.435 / $0.87`; Flash `$0.0028 / $0.14 / $0.28`. For known counts only, `USD=(cachedInput*cachePrice + uncachedInput*inputPrice + output*outputPrice)/1,000,000` (add any applicable cache-write fee). No such counts are given for either DeepSWE report, so no dollar-per-task or output-token amount follows. Its ~$0.85M/$2.62M figures are **RL training spend**, not inference cost. [AA's MiMo-V2.6-Pro page](https://artificialanalysis.ai/models/mimo-v2-6-pro) quotes ~$0.13 **per Intelligence Index task**, a different benchmark; its 140M index-wide generated tokens lack a comparable DeepSWE task denominator.
- **Qwen3.8-Flash-Next**: the [model card](https://huggingface.co/Qwen/Qwen3.8-Flash-Next) reports the best of two harnesses, with mini-SWE-agent best, but no effort or inference usage. Neither Datacurve's Qwen3.8 Max xhigh nor AA's Qwen3.8 Max Claude Code usage is a matching model. No defensible task-dollar or output-token value.
- **Datacurve paper's Kimi K2.6, Qwen3.6-Plus, MiMo-V2.5-Pro, GLM-5.1 and DeepSeek V4 Pro**: [paper](https://arxiv.org/html/2607.07946v1) reports version-*unknown* mini-swe-agent/provider-default results; Figure 8 graphs efficiency but prints no extractable per-model numeric cost/token labels. None can inherit a different v1.1 snapshot/effort mean. In particular do not equate GLM-5.1 with GLM-5.2/5.3 or the incomplete local GLM run.

### Explicit uncertainty and reuse rule

The two AA dollar amounts above are existing **same-row suite proxies**, not DeepSWE-only estimates. AA pools DeepSWE v1.1 (113 tasks), Terminal-Bench 4.0 (66) and SWE-Atlas-QnA (124), whereas its serialized `evals` output means are split by benchmark. There is **no published DeepSWE-only cost**, price snapshot, per-benchmark cache mix, or metric-specific token telemetry denominator; output plus the pooled dollar number does not identify that missing cost. $0.430 on the Fireworks observation is a source-reported dollar fact with a different, unknown denominator. The sole predecessor output comparator above has no holdout, is a distinct model version, and is **neither a prediction interval nor a measured V4.1 usage number**. Scores and model-family similarity never enter an output-token or cost equation. Only the two AA DeepSWE output counts and the existing source-scoped Fireworks cost refer directly to their named targets.
