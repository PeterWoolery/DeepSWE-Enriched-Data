# Independent remaining-usage integration review (2026-09-29)

**Verdict: numeric integration and source-row isolation check out; presentation needs corrections before treating the chart/export labels as metric-specific evidence.** Reviewed `docs/inference-source-review.md`, the working diff, scenario builders, UI/export consumers, and tests. This is a review, not an implementation change.

## Actionable findings

1. **Important — directly reported AA output is still marked as an estimate in the chart and export.** In `src/components/ExplorerChart.tsx:553,573`, every scenario point and selected X guide says `EST`, including all ten `same-source-deepswe-mean` output values. `src/components/ExplorerChart.tsx:307` calls a selected AA output mean an “estimated scenario”; `src/lib/exports.ts:52,168` calls these rows `estimated_usage_scenario` without making the record-level distinction (the nested `outputEvidenceType` does preserve it). A reader can mistake a directly reported benchmark mean for an inferred token count, especially when exporting the chart SVG or consuming CSV by record type. Keep the separate scenario layer and unchanged approved measurement fields, but label the output *metric* as source-reported AA DeepSWE mean in its point/guide/export record, with cost/time remaining estimates or references.

2. **Important — one Grok provenance sentence incorrectly assigns the Meta effort mismatch to xAI.** `src/lib/usage-scenarios.ts:426` uses the shared description “Different benchmark, and Meta xhigh→max effort mismatch” for both Meta and Grok. The Grok reference and target efforts are all **high**; its weakness is an adjacent-version, cross-benchmark transfer, not xhigh→max. This sentence is published in the results table, evidence panel, methodology page, and JSON/CSV exports. Branch the description by target. The numeric Grok projection itself matches the reviewed inputs.

3. **Important — chart annotation misstates the dollar provenance beside AA direct token means.** `src/components/ExplorerChart.tsx:513` says “only its dollar cost is pooled across the suite” for *every* same-source AA output scenario. For the seven earlier AA variants, the plotted cost is a transferred estimate or a **different Datacurve run's** cost, not the AA pooled suite value; for Fable and the two DeepSeek variants the cost really is the unchanged AA suite proxy. This text is displayed even for the cross-run-cost AA variants when viewing output tokens. Make this explanation conditional on `costScenarioType`, or describe the AA suite dollars as contextual inputs only when applicable. The scenario structures and detailed cost methods already retain the correct distinction.

4. **Minor — AA output population is described more strongly by the shared X axis than the source proves.** `src/lib/comparison.ts:10` and `src/components/ExplorerChart.tsx:388-390` call the axis “output tokens per scored rollout attempt,” but `docs/inference-source-review.md:37` identifies AA's `mean.outputTokens` as an AA DeepSWE **task-attempt** mean with no published output-telemetry-specific sample count. The point's own `outputUnit` gets this right; clarify in the shared axis/legend that scored-rollout scope describes Datacurve measurements, while AA direct source means have source-specific attempt/telemetry scope. Avoid implying a shared denominator across publishers.
